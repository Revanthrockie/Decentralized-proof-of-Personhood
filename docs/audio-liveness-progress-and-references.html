Current Implementation Status

The visual (gesture-based) liveness pipeline and the full mint pipeline (challenge → verify → IPFS → Soulbound Token) are functional end-to-end and demo-able today. The system currently supports one liveness modality (vision); this phase adds a second, independent modality (voice), following the same "nothing leaves the device unverified" design principle already used for the camera flow.

Planned implementation, which slots directly into the existing architecture:

  • Backend: extend the CHALLENGES list with an audio type carrying a randomly selected sentence; add a verification step that runs speech-to-text on the submitted clip and scores it against the prompted sentence (word-error-rate / edit-distance threshold) plus basic replay/spoof heuristics (spectral flatness, compression-artifact and energy-variance checks) before authorizing a mint — mirroring how the verify endpoint already gates on the visual challenge.
  • Frontend: a new AudioChallengeRecorder.jsx component (parallel to the existing ChallengeRecorder.jsx) to capture the mic clip, show a waveform/recording indicator, and submit it alongside the wallet address.
  • Privacy stance: transcription/scoring is intended to run within the request cycle and discard the raw audio immediately after scoring (not persisted), consistent with the project's no-raw-biometric-storage claim.

Current status: architecture and approach finalized; implementation in progress, targeting the same two integration points (/challenge, /verify) used by the visual flow.
